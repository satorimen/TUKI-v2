# ИТОГОВЫЙ ПЛАН РЕАЛИЗАЦИИ: TUKI — платформа-сваха для ремонта (Израиль)

## 1. Зафиксированные решения

| Параметр | Решение |
|----------|---------|
| Продукт | Reverse-marketplace: клиент описывает задачу ИИ-ассистенту → мастера предлагают → выбор → контакт передаётся |
| Модель | **«Сваха»**: платформа сводит стороны, далее сделка идёт в WhatsApp напрямую. Платформа не посредник в деньгах и коммуникации |
| Рынок | Израиль, вся страна через 4 гео-кластера (Гуш-Дан, Иерусалим, Хайфа+Север, Беэр-Шева+Юг) |
| Языки | Иврит (RTL, основной) + русский + английский. ИИ определяет язык автоматически |
| Деньги/телефоны | ₪ (ILS), формат +972, WhatsApp-ссылки wa.me/972... |
| Монетизация | Фаза 1: бесплатно → Фаза 2: SaaS-подписка мастеров (вне скоупа MVP) |
| Стек | Next.js 14 + TypeScript + Tailwind + Supabase + Gemini + Cloudflare R2 |
| Бюджет | 0 ₽/мес (~500-1000 пользователей) |

## 2. Ключевые улучшения против прошлой версии плана

1. **Adapter-паттерн для ИИ и БД** — работа не блокируется отсутствием API-ключей. Строю на мок-провайдерах, реальные ключи подключаются через `.env` в любой момент
2. **Гео без Google Maps** — статическая таблица городов Израиля → кластер. Выбор города из списка. Ноль внешних гео-зависимостей
3. **Без внутреннего чата** — согласно модели «сваха»: после выбора исполнителя только wa.me-ссылка. Минус целый модуль
4. **6 Milestone'ов вместо 11 этапов** — каждый заканчивается тестируемым результатом
5. **git init + план сохраняется в репозиторий** (`PLAN.md` с чекбоксами) — план переживает сессии
6. **Уведомления поэтапно**: in-app (M4) → email (M5) → WhatsApp-бот (M7, после запуска)
7. **От вас нужно только 2 аккаунта** (Gemini к M2, Supabase к M3), а не 4 сразу

## 3. Архитектура MVP

```
Next.js (Vercel, 0₽)
├── /src/app          — страницы: чат создания ТЗ, лента мастера, отклики, профили, админка
├── /src/lib/ai       — AIProvider интерфейс + GeminiProvider + MockProvider
├── /src/lib/matching — кластерный матчинг (город→кластер→специализация→рейтинг)
├── /src/lib/db       — Repository-слой над Supabase (+ мок для разработки)
├── /src/i18n         — he (RTL) / ru / en, словари next-intl
└── /supabase         — SQL-миграции
Хранение фото: Cloudflare R2 (10ГБ, 0₽)
```

## 4. Дорожная карта

### M1: Фундамент (1 сессия) — ключи НЕ нужны
- [ ] Проверить окружение (node ≥18, npm), при отсутствии — сообщить
- [ ] `git init`, `.gitignore`, README
- [ ] Инициализация Next.js 14 + TS + Tailwind + ESLint
- [ ] i18n: next-intl, локали he/ru/en, переключение `dir="rtl"/"ltr"`, шрифт с ивритом (Heebo/Rubik), логические свойства Tailwind (ms/me)
- [ ] Сохранить этот план как `PLAN.md` + краткий `PIVOT_ISRAEL.md` (дополнение к PRD: смена рынка, модель «сваха», кластеры)

- **Результат:** пустое приложение с рабочим RTL-переключением языков. Первый коммит.

### M2: ИИ-ассистент (2-3 сессии) — рисковейшая часть, делается рано
- [ ] `AIProvider` интерфейс: `parseTask(text) → ParsedTask` (тип работ, площадь, бюджет ₪, сроки, город, уточняющие вопросы, разбиение на подзадачи)
- [ ] `MockProvider` — детерминированные ответы для разработки/демо
- [ ] `GeminiProvider` — мультиязычные промпты (иврит/рус/англ), JSON-выход, PII-очистка
- [ ] Страница `/new-task`: чат-интерфейс (ввод текста, ответы ИИ, уточнения), карточка ТЗ с редактированием, публикация (пока в мок-БД)
- [ ] Тестовый набор заявок на 3 языках (включая сленг: «надо покрасить комнату», «צריך לצבוע חדר»)
- **Критерий:** ≥85% тестовых заявок парсятся корректно; карточка ТЗ формируется на языке пользователя
- **Результат:** демо-сценарий «написал текстом → получил ТЗ» работает (на моках; с ключом Gemini — на реальном ИИ)

### M3: Данные и пользователи (2-3 сессии) — нужен Supabase-аккаунт
- [ ] SQL-миграции: `users, masters, tasks, bids, reviews` (+ статусы ТЗ: draft→published→assigned→completed)
- [ ] RLS-политики, генерация TS-типов
- [ ] Auth: телефон OTP (+972) / email magic link
- [ ] Онбординг мастера: специализация (категории работ), города работы (→кластеры), опыт, портфолио
- [ ] Подключение реального Supabase вместо мока (Repository-слой не меняется)
- **Результат:** реальная регистрация, профили мастеров хранятся в БД

### M4: Маркетплейс-ядро (3-4 сессии)
- [ ] Матчинг: город ТЗ → кластер → мастера по специализации; при <3 мастерах — расширение на соседний кластер
- [ ] Лента мастера `/master/feed`: карточки ТЗ, фильтры (тип, бюджет, город)
- [ ] Отклик мастера (цена ₪, срок, сообщение); лимит откликов на ТЗ; отклики конкурентов не видны
- [ ] Список откликов клиенту + ранжирование «Лучшее соответствие» (рейтинг×цена)
- [ ] Выбор исполнителя → обеим сторонам wa.me-ссылка с предзаполненным сообщением; статус ТЗ → assigned
- [ ] Загрузка фото в R2 (прикрепление к ТЗ)
- [ ] In-app уведомления (колокольчик): новая заявка / новый отклик / вас выбрали
- **Результат:** полный цикл «заявка → отклики → выбор → WhatsApp-контакт» на реальной БД

### M5: Доверие и управление (2 сессии)
- [ ] Отзывы: опросник по 5 параметрам (качество, смета, пунктуальность, чистота, коммуникация), расчёт рейтинга, ответ мастера
- [ ] Механика завершения: через 7 дней после выбора — напоминание клиенту «состоялась ли сделка? оставьте отзыв»
- [ ] Email-уведомления (Resend, 3к/мес бесплатно)
- [ ] Админка `/admin`: метрики (заявки, отклики, конверсии, активные мастера), бан пользователей, модерация отзывов
- **Результат:** рейтинги работают, вы можете управлять платформой

### M6: Запуск (1-2 сессии) — нужен Vercel-аккаунт

- [ ] PWA-манифест, SEO, метатеги на 3 языках
- [ ] Аналитика: события (создание ТЗ, отклик, выбор, отзыв)
- [ ] Деплой на Vercel, `.env.example` + инструкция в README
- **Результат:** живой MVP по публичному URL

### M7 (опционально, после валидации): WhatsApp-бот

## 7. Definition of Done MVP
1. Клиент создаёт ТЗ через ИИ-чат на иврите/русском/английском
2. Мастер регистрируется, видит релевантные ТЗ в своём кластере, откликается
3. Клиент выбирает исполнителя → обе стороны получают WhatsApp-контакт
4. Отзывы и рейтинги работают
5. Админка показывает воронку
6. Деплой на Vercel работает

# БЛОК 1. ВИДЕНИЕ И СТРАТЕГИЯ

## 1. Executive Summary

**Продукт** — двусторонняя платформа (маркетплейс обратного спроса), соединяющая клиентов, нуждающихся в строительных или ремонтных работах, с профессиональными мастерами.

**Ключевое отличие от существующих решений:** Вместо традиционного каталога услуг (где клиент ищет исполнителя) приложение использует **ИИ-ассистента** для интуитивного сбора заявки от клиента в свободной форме — голосом или текстом. ИИ превращает «поток сознания» в структурированное ТЗ за секунды. Платформа работает по модели **«клиент создаёт спрос — мастера предлагают решение»** (обратный аукцион).

**Бизнес-модель (двухфазная):**
- **Фаза 1 «Горячий старт»** — сервис абсолютно бесплатен для всех участников. Цель: преодолеть проблему «курицы и яйца», набрать критическую массу мастеров и обучить ИИ на реальных диалогах.
- **Фаза 2 «Монетизация»** — после достижения целевых метрик ликвидности вводится **фиксированная ежемесячная подписка для мастеров** (SaaS-модель). Для клиентов сервис остаётся бесплатным навсегда.

**Платформы:** iOS (нативное), Android (нативное), Веб (адаптивный PWA).

**MVP-фокус:** Чат-ассистент с ИИ-парсингом ТЗ + обратный аукцион + базовый матчинг по гео и специализации. CV-оценка по фото и ИИ-модерация чата переносятся в V2.

## 2. Видение и миссия продукта

### Продуктовое видение (Product Vision)

> **Для** владельцев квартир и домов, **которые** нуждаются в ремонтных или строительных работах, **платформа** — это ИИ-ассистент, **который** понимает задачу в свободной форме и за минуты подбирает проверенных мастеров с готовыми предложениями, **в отличие от** Авито, Профи.ру и каталогов услуг, **наш продукт** устраняет барьер «не знаю, как назвать услугу» и превращает поиск исполнителя из многочасового в десятиминутный.

### Миссия

Сделать ремонт и строительство **прозрачными, предсказуемыми и доступными** — убрать информационный разрыв между клиентом (который не знает терминологии) и мастером (которому нужно чёткое ТЗ).

### Принципы продукта (Product Principles)

| # | Принцип | Что значит на практике |
|---|---------|----------------------|
| 1 | **Клиент — гость, а не работник** | Клиент не должен разбираться в терминах. ИИ берёт на себя перевод с бытового на технический. |
| 2 | **Прозрачность экономики** | Никаких скрытых комиссий с чека. Мастер знает свою цену заранее. |
| 3 | **Сервис = ассистент, не посредник** | Платформа помогает, а не встаёт между сторонами. Прямая оплата, прямые контакты. |
| 4 | **Доверие через данные** | Рейтинг строится на детализированных отзывах, а не на «звёздах за красивые глаза». |
| 5 | **ИИ усиливает, не заменяет** | ИИ не принимает решения за людей — он структурирует информацию и снижает когнитивную нагрузку. |

## 3. Проблема и решение

### 3.1. Проблемы клиента (заказчика)

| Боль | Текущее решение (без нас) | Почему это плохо |
|------|--------------------------|-----------------|
| **Не знаю, как назвать услугу** | Листает каталог категорий Авито/Профи.ру | Не находит нужное, тратит 30-60 минут, сдаётся |
| **Не понимаю объём работ** | Вызывает мастера на «замер» (часто платный) | Тратит время, рискует нарваться на «развод» |
| **Боюсь переплатить** | Звонит нескольким мастерам, сравнивает наугад | Не может оценить адекватность цены — нет экспертизы |
| **Не доверяю отзывам** | Читает отзывы на площадках | Не верит — знает про накрутки, фейковые отзывы |
| **Сложно описать задачу** | Пытается заполнить длинные формы | Бросает на середине, уходит к первому попавшемуся |

### 3.2. Проблемы мастера (исполнителя)

| Боль | Текущее решение (без нас) | Почему это плохо |
|------|--------------------------|-----------------|
| **Непредсказуемые расходы на маркетинг** | Платит 10-15% комиссии с каждого чека | На крупном ремонте (200к+) отдаёт 20-30к комиссии |
| **Дорогие и холодные лиды** | Покупает лиды у агрегаторов, размещает платные объявления | 80% лидов — «холодные» (клиент не понял, что ему нужно) |
| **Демпинг конкурентов** | Видит, как конкуренты сбивают цену в открытую | Теряет заказы, вынужден снижать и свою цену |
| **Трата времени на замеры** | Едет на другой конец города просто для оценки | Тратит 2-3 часа на заказ, который может не получить |
| **Нет нормального CRM** | Ведёт клиентов в блокноте / WhatsApp | Теряет историю, не может показать портфолио структурированно |

## 4. Уникальное ценностное предложение (UVP)

### 4.1. UVP для клиента

> **«Опиши проблему голосом — получи предложения от проверенных мастеров за минуты. Бесплатно».**

**Три столпа:**
1. **Нулевой барьер входа** — не нужно знать терминологию, просто говоришь как есть.
2. **Проактивность** — не ты ищешь мастера, а мастера приходят к тебе с готовыми предложениями.
3. **Цена = ноль** — клиент никогда не платит платформе.

### 4.2. UVP для мастера

> **«Платишь фиксированную подписку — все заработанное твоё. Качественные лиды с готовым ТЗ и фото».**

**Три столпа:**
1. **Предсказуемая экономика** — фиксированный расход на маркетинг, защита от комиссий с крупных чеков.
2. **Горячие лиды** — ИИ уже собрал ТЗ и фото, не нужно ехать на замер вслепую.
3. **Меньше демпинга** — заявку видят только релевантные мастера, а не вся толпа.

### 4.3. Конкурентное позиционирование (упрощённое)

## 5. Целевая аудитория и Personas

### 5.1. Сегментация аудитории

**Сторона клиента (спрос):**
- Владельцы квартир, делающие косметический ремонт
- Владельцы квартир, делающие капитальный ремонт
- Домовладельцы / собственники загородной недвижимости
- Арендодатели, готовящие квартиру к сдаче
- Малый бизнес (кафе, офисы), нуждающийся в ремонтных работах

**Сторона мастера (предложение):**
- Мастера-одиночки (сантехники, электрики, отделочники)
- Мини-бригады (2-4 человека, узкая специализация)
- Бригады полного цикла (5+ человек, комплексный ремонт)
- Подрядчики / прорабы (берут объём, распределяют по субподрядчикам)

### 6.2. Подробное описание шагов

#### Шаг 1. Сбор заявки (Сторона Заказчика)

Пользователь открывает приложение и вместо сложного каталога видит **чат-интерфейс**.

1. **Ввод в свободной форме:** Клиент пишет или наговаривает голосом:
   > *«Нужно переклеить обои в комнате 18 кв.м. Старые снять, стены выровнять. И еще в кухне капает кран. Бюджет — до 15 тысяч, готов начать на следующей неделе».*

2. **Работа ИИ-ассистента:**
   - **Извлечение сущностей:** ИИ раскладывает сообщение на два микротаска:
     1. Подготовка стен и поклейка обоев (18 кв.м.)
     2. Ремонт кухонного крана
   - **Уточняющие вопросы:** ИИ задаёт ненавязчивые вопросы:
     > *«Уточните, какой тип обоев планируете? И есть ли уже материалы?»*
   - **Запрос медиа:** ИИ просит загрузить фото комнаты и крана (в MVP — для визуального контекста мастера; в V2 — Computer Vision для оценки объёма работ).

3. **Результат:** ИИ формирует из сломанного текста **структурированную карточку задания (ТЗ)**. Клиент проверяет её и нажимает «Опубликовать».

#### Шаг 2. Обратный аукцион (Сторона Мастеров)

На стороне мастеров работает **умная лента** потенциальных заказов, отфильтрованная по их гео, рейтингу и специализации.

1. **Умный матчинг:** Отделочники из района клиента получают уведомление о поклейке обоев, а сантехники — о кране.
2. **Создание предложения:** Мастер видит готовое ТЗ, фото и бюджет. Он предлагает своё решение: указывает цену, сроки и пишет сопроводительное сообщение.
3. **Выбор:** Клиент получает уведомления о новых предложениях. Платформа подсвечивает **«Лучшее соответствие»** на основе рейтинга, цены и отзывов. Клиент выбирает исполнителя.

#### Шаг 3. Исполнение и контроль качества

1. **Прямая оплата:** Оплата за ремонт происходит **напрямую** между клиентом и мастером (наличными, переводом). Платформа не выступает посредником в деньгах.
2. **ИИ-сопровождение:** Платформа остаётся каналом коммуникации. ИИ присылает мастеру чек-листы по этапам работ, а клиенту — статус-апдейты.
3. **Отзывы:** По итогу сделки ИИ собирает детализированный отзыв (опросник по пунктуальности, чистоте, соблюдению сметы), формируя рейтинг мастера.

### 10.2. Детальное описание: ИИ-парсинг ТЗ (MVP)

**Цель:** Превратить «поток сознания» клиента в структурированное ТЗ.

**Вход:** Свободный текст или транскрипция голосового ввода.
> *«Нужно переклеить обои в комнате 18 кв.м. Старые снять, стены выровнять. И еще в кухне капает кран. Бюджет — до 15 тысяч, готов начать на следующей неделе»*

**Выход:** Структурированный JSON с извлечёнными сущностями.

```json
{
  "tasks": [
    {
      "type": "Обойные работы",
      "subtypes": ["Демонтаж старых обоев", "Выравнивание стен", "Поклейка обоев"],
      "area_sqm": 18,
      "room_type": "комната",
      "wallpaper_type": null,
      "materials_provided": null
    },
    {
      "type": "Сантехника",
      "subtypes": ["Ремонт смесителя / крана"],
      "location": "кухня",
      "problem": "капает кран"
    }
  ],
  "budget_max": 15000,
  "timeline": "next_week",
  "location": null,
  "missing_fields": ["wallpaper_type", "materials_provided", "location"],
  "clarifying_questions": [
    "Какой тип обоев планируете (флизелиновые, виниловые, бумажные)?",
    "Материалы уже куплены или нужно приобрести?",
    "В каком районе находится объект?"
  ]
}
```

**Требования к LLM:**
- Извлечение сущностей: тип работ, подтипы, площадь, бюджет, сроки, локация
- Определение неполноты и генерация уточняющих вопросов
- Разбиение на независимые микротаски
- Устойчивость к орфографическим ошибкам, разговорной речи, сленгу
- Поддержка русского языка (включая региональную лексику)

### 10.3. Детальное описание: Умный матчинг (MVP → V3)

**MVP — правило-ориентированный матчинг:**
```
Алгоритм матчинга (MVP):
1. Фильтр по специализации мастера (точное совпадение с type/subtypes ТЗ)
2. Фильтр по гео (радиус от локации мастера до локации ТЗ)
3. Ранжирование по рейтингу мастера (базовый)
4. Учитывать статус мастера (активен, не в отпуске)

Результат: список мастеров, получающих уведомление о ТЗ
```

**V3 — ML-ориентированный матчинг:**
```
Алгоритм матчинга (V3):
- Feature engineering: профиль мастера, история сделок, рейтинги,
  гео-данные, сезонность, цена, специализация
- Модель: предсказание P(сделка завершена успешно | мастер, ТЗ)
- Учитывать: вероятность отклика мастера, вероятность выбора клиентом,
  вероятность успешного завершения
- Оптимизация: максимизация ликвидности платформы
```

### 10.4. Детальное описание: Computer Vision (V2)

**Цель:** Предварительная оценка объёма работ по фото без выезда мастера.

**Примеры применения:**
| Сценарий | Что оценивает CV | Польза |
|----------|----------------|--------|
| Фото стен перед поклейкой обоев | Кривизна стен (нужен ли слой штукатурки 5мм или 2см) | Мастер сразу понимает объём |
| Фото крана / трубы | Тип поломки, марка сантехники | Мастер понимает, какие запчасти взять |
| Фото потолка | Площадь, тип покрытия | Расчёт расхода материалов |
| Фото пола | Состояние, необходимость демонтажа | Оценка трудоёмкости |

**Технические требования (для V2):**
- Модель классификации / сегментации по типам объектов ремонта
- Оценка метрик (площадь, кривизна, повреждения)
- Вывод в структурированном виде (JSON) для интеграции в карточку ТЗ
- Человекочитаемая интерпретация («Стены достаточно ровные, потребуется минимальная подготовка»)

### 10.5. Детальное описание: ИИ-модерация чата (V2)

**Цель:** Предотвращение конфликтов и потерю договорённостей.

**Функционал:**
| Триггер | Действие ИИ |
|---------|-------------|
| Стороны договорились об изменении сметы | Предлагает зафиксировать в чек-листе приложения |
| Обнаружены агрессивные слова / конфликт | Предупреждение + предложение медиации |

| Речь идёт о предоплате / деньгах | Предупреждение о рисках, совет о безопасной оплате |
| Стороны договорились о дате работ | Авто-добавление в календарь сделки |

## 11. MVP-скоуп vs Post-MVP

### 11.1. Что входит в MVP

**Цель MVP:** Проверить основную гипотезу — «клиенты готовы описывать задачу голосом/текстом через ИИ-ассистент, а мастера готовы откликаться через обратный аукцион».

| Компонент | В MVP | Обоснование |
|-----------|-------|-------------|
| Регистрация (телефон) | ✅ | Минимальный барьер |
| Чат-ассистент (текст + голос) | ✅ | Ключевая дифференциация |
| ИИ-парсинг ТЗ + уточняющие вопросы | ✅ | Ключевая ценность |
| Загрузка фото (без CV) | ✅ | Контекст для мастера |
| Публикация ТЗ | ✅ | Основной процесс |
| Матчинг (базовый, правило-ориентированный) | ✅ | Необходим для аукциона |
| Лента ТЗ для мастера + отклики | ✅ | Сторона предложения |
| Список откликов + «Лучшее соответствие» | ✅ | Сторона спроса |
| Чат между сторонами (текст + фото) | ✅ | Коммуникация |
| Отзывы (опросник по параметрам) | ✅ | Капитал доверия |
| Профили мастеров (базовые) | ✅ | Прозрачность |
| Уведомления (push) | ✅ | Удержание |
| Админ-панель (базовая) | ✅ | Модерация |
| **Подписка и платежи** | ❌ | Фаза 2 монетизации |
| **Верификация документов** | ⚠️ Базовая | Полная — в V1 |
| **ИИ-чеклисты этапов** | ⚠️ Базовые шаблонные | ИИ-генерация — в V1 |
| **Computer Vision** | ❌ | V2 |
| **ИИ-модерация чата** | ❌ | V2 |

| Компонент | Ответственность | Ключевые характеристики |
|-----------|----------------|------------------------|
| **API-шлюз** | Единая точка входа, аутентификация, роутинг | REST + WebSocket (для чата и real-time обновлений) |
| **Сервис пользователей** | Регистрация, профили, роли, верификация | Мультитенантная модель ролей (клиент/мастер/админ) |
| **Сервис заявок (ТЗ)** | CRUD ТЗ, статусы, черновики | Интеграция с ИИ-слоем для парсинга |
| **Сервис аукциона** | Отклики, выбор исполнителя, анти-демпинг | Бизнес-логика «слепого» аукциона (мастера не видят чужие отклики) |

| **Сервис матчинга** | Подбор мастеров под ТЗ | Правило-ориентированный (MVP) → ML (V3) |
| **ИИ-слой** | LLM-вызовы, промпт-инжиниринг, CV (V2) | Асинхронные задачи, кэширование, fallback-логика |
| **Сервис уведомлений** | Push/SMS/email | Очередь, шаблоны, retry-логика |

### 12.3. Архитектурные паттерны и принципы

| Принцип | Применение |
|---------|-----------|
| **Микросервисная (или модульный монолит на старте)** | Изолированные домены (пользователи, заявки, аукцион, чат, отзывы). На MVP допустим модульный монолит с последующим выделением сервисов. |
| **API-first** | Все клиенты (iOS/Android/Web) работают через единый API. Контракты описаны (OpenAPI/GraphQL). |
| **Event-driven для асинхронных процессов** | ИИ-парсинг, матчинг, уведомления — через очереди сообщений. |
| **Stateless сервисы + внешнее хранилище сессий** | Горизонтальное масштабирование без привязки сессий к инстансам. |
| **CQRS для чтения ленты ТЗ** | Оптимизация чтения (лента мастера) отдельно от записи (создание ТЗ). |

### 13.2. LLM-интеграция: архитектурные требования

LLM — критический компонент, требует особого внимания:

| Требование | Описание |
|-----------|----------|
| **Мультипровайдерность** | Абстракция над провайдерами (OpenAI, Anthropic, локальные модели, Yandex GPT и т.д.). Возможность переключения без изменения бизнес-логики. |
| **Fallback-логика** | При недоступности/ошибке основного провайдера — автоматический переход на резервный. |
| **Кэширование** | Кэширование типовых ответов (одинаковые уточняющие вопросы для схожих задач). |
| **Таймауты и retry** | Жёсткие таймауты (пользователь не ждёт > 5 сек), экспоненциальный backoff. |
| **Graceful degradation** | Если ИИ недоступен — fallback на ручной ввод ТЗ (формы). Продукт работает без ИИ. |
| **Промпт-менеджмент** | Версионирование промптов, A/B-тестирование, хранилище промптов отдельно от кода. |
| **Оценка качества** | Логирование всех вызовов + ручная разметка качества для последующего fine-tuning. |
| **Контроль стоимости** | Мониторинг расхода токенов, бюджетные лимиты, алерты при превышении. |
| **Приватность** | PII-фильтрация перед отправкой в облачный LLM (удаление телефонов, адресов из текста). |

### 14.2. Жизненный цикл ТЗ (State Machine)

```
                         ┌───────────┐
                         │   DRAFT   │  (черновик, ИИ собирает данные)
                         └─────┬─────┘
                               │ Клиент публикует
                               ▼
                         ┌───────────┐
              ┌────────▶│ PUBLISHED │  (видна мастерам, сбор откликов)
              │          └─────┬─────┘
              │                │ Мастер откликается
              │                ▼
              │          ┌───────────┐
              │          │ IN_AUCTION│  (есть отклики, ожидание выбора)
              │          └─────┬─────┘
              │                │ Клиент выбирает
              │                ▼
              │          ┌───────────┐
              │          │  ASSIGNED │  (исполнитель выбран, чат активен)
              │          └─────┬─────┘
              │                │ Мастер начинает работы
              │                ▼
              │          ┌───────────┐
              │          │IN_PROGRESS│  (работы выполняются)
              │          └─────┬─────┘
              │                │ Мастер завершил + клиент подтвердил
              │                ▼
              │          ┌───────────┐
              │          │ COMPLETED │  (работы завершены, отзыв)
              └──────────┘     │      └───────────┘
              │ Таймаут        │
              │ (истёк срок)   │ Отмена (любой этап)
              │                ▼
              │          ┌───────────┐
              └──────────│ CANCELLED │
                         └───────────┘
              │
              ▼
         ┌───────────┐
         │  EXPIRED  │  (никто не выбран за срок)
         └───────────┘
```

### 14.3. Денормализация и оптимизации

| Потребность | Решение |
|------------|---------|
| Быстрая лента ТЗ для мастера | Материализованное представление / кэш Redis: ТЗ отсортированные по гео+специализации |
| Агрегированный рейтинг мастера | Кэшированное поле в `Master` (пересчёт по триггеру нового отзыва) |
| Подсчёт откликов на ТЗ | Счётчик в `Task` (обновляется триггером) |
| История чата | Пагинированное чтение, индекс по `conversation_id + created_at` |

### 16.2. Фаза 1: «Горячий старт» (Бесплатно)

**Цель этапа** — решить проблему «курицы и яйца», набрать базу мастеров и обучить ИИ на реальных диалогах.

| Элемент | Описание |
|---------|----------|
| **0% комиссии и 0 рублей за отклики** | Платформа работает как бесплатный агрегатор-ассистент |
| **Прямые контакты** | Мастера и клиенты могут свободно обмениваться контактами и договариваться вне платформы |
| **Фокус на удержании (Retention)** | Чтобы пользователи не уходили после первой сделки, ИИ удерживает коммуникацию внутри чата (чек-листы, напоминания о этапах ремонта) |
| **Ключевая метрика** | Количество успешных сделок и оставленных отзывов — это формирует «капитал доверия» для Фазы 2 |

**Почему бесплатно — это стратегия, а не благотворительность:**
- На рынке с сильной конкуренцией (Авито, Профи.ру) бесплатный период — это **Customer Acquisition Strategy**. Стоимость привлечения мастера через «бесплатно» значительно ниже, чем через платный канал.
- Каждый диалог клиента с ИИ — это **обучающие данные** для будущих улучшений. Бесплатный период = сбор датасета.
- Каждая завершённая сделка с отзывом — это **сетевой эффект**. Новые клиенты приходят, видя живую активность.

### 16.3. Фаза 2: Переход на SaaS-подписку

**Триггер перехода** — достижение метрик ликвидности (см. раздел 17.3):
- Мастера регулярно получают заказы (≥ 5 завершённых сделок в месяц для активных)
- Время до отклика стабильно < 60 минут
- Доля успешных сделок > 50%

| Элемент | Описание |
|---------|----------|
| **Монетизация мастеров** | Ежемесячная подписка: 990–2990 руб/мес (в зависимости от специализации и региона) |
| **Freemium для мягкого перехода** | Бесплатный лимит: 3 отклика в месяц или доступ только к ТЗ с малым бюджетом. Для активной работы — подписка. |
| **Для клиентов — навсегда бесплатно** | Сохраняет высокий поток входящих заявок, что оправдывает стоимость подписки для мастеров |

**Почему фикс-подписка сработает лучше комиссии:**

| Аргумент | Объяснение |
|----------|-----------|
| **Предсказуемость для мастера** | Мастер знает точную сумму расхода на маркетинг. Заплатил 1990 ₽ — всё. Нет «сюрпризов» с крупных чеков. |
| **Защита от крупных комиссий** | На ремонте за 500 000 ₽ комиссия 15% = 75 000 ₽. Подписка 2990 ₽/мес = 35 880 ₽/год. Мастер в плюсе даже при 1 крупном заказе. |
| **Стимул объёма** | Чем больше заказов мастер закрывает, тем выгоднее подписка. Это стимулирует активность на платформе. |
| **Предсказуемый revenue для платформы** | MRR (Monthly Recurring Revenue) проще прогнозировать, чем комиссионный доход. |

### 16.6. Юнит-экономика: ключевые формулы

> ⚠️ Конкретные цифры не приводятся (не запрашивались) — даются формулы для отслеживания.

**Для мастера (Customer):**
```
CAC (Customer Acquisition Cost для мастера) =
    Маркетинговые расходы на привлечение мастера /
    Количество привлечённых мастеров

LTV мастера (Lifetime Value) =
    Средний чек подписки × Gross Margin × (1 / Churn Rate)

LTV / CAC ratio (целевой) > 3   (норма для SaaS)

Payback Period (период окупаемости) =
    CAC / (Средний чек подписки × Gross Margin)
    Цель: < 3 месяцев
```

**Для платформы:**
```
MRR (Monthly Recurring Revenue) =
    Σ(Активные подписки × Цена тарифа)

ARR (Annual Recurring Revenue) = MRR × 12

Churn Rate (отток мастеров) =
    (Мастера, отписавшиеся за период) /
    (Мастера с подпиской на начало периода) × 100%
    Цель: < 5% месячных

ARPU (Average Revenue Per User - мастер) =
    MRR / Количество активных мастеров

Net Revenue Retention =
    (MRR начало + Upgrades − Downgrades − Churn) /
    MRR начало × 100%
    Цель: > 100% (рост даже без новых клиентов)
```

## 17. Ключевые метрики

### 17.1. North Star Metric (NSM)

> **North Star Metric = Количество успешно завершённых сделок в месяц**

**Почему эта метрика:**
- Отражает **ценность для обеих сторон** (клиент получил услугу, мастер заработал).
- Коррелирует со здоровьем маркетплейса (ликвидностью).
- Только если сделка завершена и оставлен отзыв — платформа создаёт «капитал доверия».
- Напрямую ведёт к монетизации: мастер, завершивший сделки, охотнее платит подписку.

```
                    North Star Metric
                    ═════════════════
              Успешно завершённые сделки / месяц
                           │
           ┌───────────────┼───────────────┐
           ▼               ▼               ▼
     Спрос (клиенты)  Ликвидность     Предложение (мастера)
     · Заявок/мес     · Время до      · Активных мастеров
     · Конверсия в      отклика       · Откликов/мастер
       публикацию     · Конверсия в   · Завершённых/мастер
     · Retention       выбор          · Retention
                       исполнителя
```

| **Activation** | Время до первого отклика | От регистрации до отклика | < 24 часа |
| **Retention** | M1 / M3 retention | Активны 1/3 месяца подряд | M1 > 40% |
| **Retention** | Активных мастеров (MAU) | Сделали отклик за месяц | Рост MoM |
| **Revenue** | % конверсии в подписку (Фаза 2) | Free → Paid | > 15% |
| **Revenue** | MRR | Monthly Recurring Revenue | Рост MoM |
| **Revenue** | Churn rate (мастеров) | Отток платящих | < 5%/мес |
| **Referral** | Мастеров по рекомендации | Пришли от других мастеров | Рост доли |

### 17.3. Метрики ликвидности маркетплейса

Ликвидность — **критическая метрика** для двусторонней платформы. Это процент заявок, по которым состоялась сделка.

| Метрика | Формула | Цель |
|---------|---------|------|
| **Time-to-first-bid** | Медианное время от публикации ТЗ до первого отклика | < 60 мин |
| **Time-to-assign** | Медианное время от публикации до выбора исполнителя | < 24 часа |
| **Fill rate** | % опубликованных ТЗ, по которым получен ≥ 1 отклик | > 80% |
| **Assign rate** | % ТЗ, по которым выбран исполнитель | > 50% |
| **Completion rate** | % назначенных сделок, завершённых успешно | > 70% |
| **Take rate** (Фаза 2) | % мастеров с подпиской от активных | > 30% |
| **Сторона-узкое-место** | Баланс спрос/предложение | Поддерживать ratio |

**Контроль плотности (liquidity density):**
```
Плотность мастера = (Количество ТЗ по специализации в радиусе R) / (Количество мастеров этой специализации)

Цель: Плотность ≥ 3 ТЗ на мастера в месяц
      (мастер должен иметь возможность выбора, а не хватать любое ТЗ)
```

### 17.4. Метрики качества ИИ

| Метрика | Описание | Цель |
|---------|----------|------|
| **Parsing accuracy** | % ТЗ, где ИИ корректно извлёк все сущности | > 85% |
| **Edit rate** | % ТЗ, отредактированных клиентом после ИИ | < 40% (иначе ИИ неточен) |
| **Clarification relevance** | % уточняющих вопросов, признанных релевантными | > 80% |
| **ИИ availability** | % времени, когда ИИ-парсинг доступен | > 99% |
| **ИИ latency** | Медианное время парсинга | < 5 сек |
| **Fallback rate** | % случаев, когда ИИ не сработал → ручной ввод | < 5% |
| **Cost per parse** | Стоимость одного ИИ-вызова | Оптимизация вниз |

## 18. Этапы запуска (Go-to-Market)

### 18.1. Гео-стратегия: «Победи в одном районе»

Двусторонние платформы не запускаются «сразу на всю Россию». Стратегия — **географическая концентрация** для достижения локальной ликвидности.

```
┌──────────────────────────────────────────────────────────────────────┐
│                      ГЕО-СТРАТЕГИЯ ЗАПУСКА                            │
├──────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   ЭТАП 0: ОДИН РАЙОН                  ЭТАП 1: ОДИН ГОРОД             │
│   ┌───────────────────┐               ┌───────────────────────┐     │
│   │  · 1 район Москвы │               │  · Весь город          │     │
│   │    (~50к жителей) │   ────────▶   │  · ~10 районов         │     │
│   │  · ~200 мастеров  │               │  · ~2000 мастеров      │     │
│   │  · Тест гипотез   │               │  · Доказательство unit │     │
│   │                   │               │    экономики            │     │
│   └───────────────────┘               └───────────┬───────────┘     │
│                                                   │                  │
│                                                   ▼                  │
│                                       ЭТАП 2: МАСШТАБ                │
│                                       ┌───────────────────────┐     │
│                                       │  · 3-5 городов         │     │
│                                       │  · Репликация модели   │     │
│                                       │  · SaaS монетизация    │     │
│                                       └───────────────────────┘     │
└──────────────────────────────────────────────────────────────────────┘
```

**Почему один район:**
- Ликвидность маркетплейса = функция плотности. В одном районе проще достичь критической массы.
- Меньше маркетинговый бюджет на тестирование гипотез.
- Быстрее цикл обратной связи (мастеры и клиенты рядом, сделки происходят быстро).

**Критерии выбора района для старта:**
| Критерий | Почему важно |
|----------|-------------|
| Высокая доля новостроек | Много ремонтов «с нуля» |
| Средний+ доход | Готовность платить за качество |
| Активный чат домового WhatsApp | Канал органического привлечения |
| Развитая инфраструктура | Мастера готовы ехать |
| Низкая концентрация конкурентов offline | Меньше инерции перехода |

### 18.2. Решение проблемы «курицы и яйца»

Двусторонние платформы сталкиваются с дилеммой: клиенты не приходят без мастеров, мастера — без клиентов.

| Стратегия | Тактика |
|-----------|---------|
| **Сначала сторона предложения** | Ручной рекрутинг первых 100-200 мастеров. Личный контакт, объяснение ценности «бесплатного периода + фикс. подписки потом». |
| **Стимулирование спроса** | Гео-таргетированная реклама в выбранном районе. Партнёрства с УК, риелторами, чатами домов. |
| **Subsidize одной стороны** | Мастерам — бесплатно (Фаза 1). Клиентам — бесплатно навсегда. Платформа субсидирует обе стороны на старте. |
| **«Прийти с командой»** | Привлекать не одиночек, а целые бригады / комьюнити мастеров (если бригадир приведёт 5 человек — мгновенный скачок ликвидности). |
| **Органический вирусный эффект** | Каждый довольный клиент = рекомендация. Каждый довольный мастер = приведёт коллег. |
| **Single-player mode** | На старте, если мастеров мало — ИИ помогает клиенту максимально чётко сформулировать ТЗ, чтобы даже малое предложение релевантных мастеров давало результат. |

### 18.3. Каналы привлечения

#### Клиенты (спрос)

| Канал | Тактика | Этап |
|-------|---------|------|
| **Гео-реклама (контекст/соцсети)** | Таргетинг на выбранный район | MVP+ |
| **Партнёрства с УК / ТСЖ** | Реклама в чатах домов, лифтах | MVP+ |
| **Риелторы** | Партнёрская программа (кто продаёт квартиру → ремонт) | V1 |
| **SEO-контент** | Статьи «как выбрать мастера», «сколько стоит поклеить обои» | V1 |
| **Сарафанное радио** | Реферальная программа (скидка/бонус за приглашение) | MVP+ |
| **Промо в App Store / Google Play** | ASO-оптимизация | MVP+ |

#### Мастера (предложение)

| Канал | Тактика | Этап |
|-------|---------|------|
| **Ручной рекрутинг (outbound)** | Личный контакт на Авито, в чатах мастеров | MVP (критично) |
| **Реферальная программа мастеров** | «Приведи коллег — получи месяц подписки» (Фаза 2) | Фаза 2 |
| **Партнёрства с учебными центрами** | Выпускники курсов ремонта | V1 |
| **Контент-маркетинг** | Кейсы «как мастера зарабатывают через платформу» | V1 |
| **Реклама в профессиональных сообществах** | Telegram-чаты мастеров, форумы | MVP+ |

### 18.4. Критерии перехода Фаза 1 → Фаза 2

Переход на монетизацию происходит **только** при достижении всех критериев:

| # | Критерий | Метрика | Целевое значение |
|---|----------|---------|------------------|
| 1 | Достаточная база мастеров | Активных мастеров MAU | ≥ 500 |
| 2 | Ликвидность доказана | Fill rate | > 80% |
| 3 | Сделки происходят | Assign rate | > 50% |
| 4 | Сделки завершаются | Completion rate | > 70% |
| 5 | Быстрый отклик | Time-to-first-bid | < 60 мин |
| 6 | Мастера видят ценность | Сделок на активного мастера/мес | ≥ 3 |
| 7 | Капитал доверия | Детализированных отзывов | ≥ 1000 |
| 8 | Спрос стабилен | Новых ТЗ/неделя | ≥ 200 |

**Триггер для реструктуризации:** Если через 6 месяцев Фазы 1 метрики не достигнуты — пересмотр стратегии (возможно, смена гео, нишевание, корректировка продукта).

## 20. Риски и митигация

### 20.1. Продуктовые риски

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| **Клиенты не понимают ИИ-ассистент** (хотят каталог) | Средняя | Высокое | A/B-тест: чат vs гибрид (чат + каталог). Обучение через онбординг. ИИ подсказывает примеры. |
| **ИИ некачественно парсит ТЗ** (ошибки, галлюцинации) | Высокая | Высокое | Человек-в-цикле: клиент всегда проверяет ТЗ. Graceful degradation на ручные формы. Fine-tuning на данных. |
| **Мастера не откликаются** (нет ликвидности) | Высокая | Критическое | Ручной рекрутинг первых 100-200 мастеров. Гео-концентрация. «Прийти с командой». |
| **Сделки уходят в оффлайн** (мастера уводят клиентов) | Высокая | Высокое | CRM-ценность платформы: если мастер ведёт бизнес в приложении, уход = потеря базы. ИИ-чеклисты, отзывы. |
| **Отток мастеров при введении подписки** | Средняя | Высокое | Плавный переход. Legacy-статус для первых 1000. Freemium-лимиты. ROI-калькулятор. |

### 20.2. Технические риски

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| **LLM-провайдер недоступен / дорогой** | Средняя | Высокое | Мультипровайдерная стратегия с fallback. On-premise модель как резерв. Бюджетные лимиты. |
| **Латентность ИИ > ожиданий пользователя** | Средняя | Среднее | Кэширование, стриминг ответов, индикатор загрузки, асинхронные задачи. |
| **Проблемы масштабирования при росте** | Низкая (MVP) | Высокое (V2+)) | Stateless-архитектура с самого начала. Горизонтальное масштабирование. |
| **Утечка персональных данных** | Низкая | Критическое | Шифрование, PII-фильтрация, аудит, соответствие 152-ФЗ. |
| **Накрутки отзывов / фрод** | Высокая | Высокое | Анти-фрод алгоритмы. Отзывы только после подтверждённой сделки. Модерация. |
| **WebSocket-соединения падают под нагрузкой** | Средняя | Среднее | Connection pooling, reconnect-логика на клиенте, fallback на polling. |

### 20.3. Рыночные риски

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| **Конкуренты копируют ИИ-ассистент** | Высокая | Среднее | Сетевой эффект: капитал доверия (отзывы, рейтинги) — долго копировать. Уникальная бизнес-модель (SaaS, не комиссия). |
| **Авито/Профи запускают аналог** | Средняя | Высокое | Фокус на нише (ремонт/строительство), где они generalists. Скорость и качество ИИ. |
| **Регуляторные изменения** (152-ФЗ, налоги) | Низкая | Среднее | Юридический комплаенс с начала. Локализация данных в РФ. |
| **Экономический спад** (меньше ремонтов) | Средняя | Высокое | Диверсификация: косметический ремонт (бюджетный) + капитальный. B2B-сегмент (офисы). |

### 20.4. Риски команды и исполнения

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| **Нехватка AI/ML экспертизы** | Средняя | Высокое | Найм специалиста на старте. Внешний консалтинг. Использование готовых LLM (не строить свою). |
| **Срыв сроков MVP** | Высокая | Среднее | Жёсткий скоуп (MoSCoW). Cut фич при риске. Декомпозиция на независимые спринты. |
| **Сложность кроссплатформенной разработки** | Средняя | Среднее | Старт с PWA (один код-base). Нативные приложения — после валидации гипотез. |

### 21.3. Бизнес-критерии запуска (Soft-launch)

MVP готов к soft-launch в одном районе при выполнении:

| # | Критерий | Цель |
|---|----------|------|
| 1 | Ручная база мастеров набрана | ≥ 50 активных мастеров в районе |
| 2 | Процесс модерации/поддержки описан | SOP готовы |
| 3 | Юридические документы готовы | Оферта, политика конфиденциальности, 152-ФЗ |
| 4 | Каналы привлечения клиентов готовы | Реклама запущена, партнёрства |
| 5 | Аналитика настроена | Трекинг событий, дашборд |
| 6 | Команда поддержки готова | Процессы обработки инцидентов |

### 21.4. Критерии успеха MVP (через 3 месяца после запуска)

| Метрика | Цель |
|---------|------|
| Новых ТЗ/неделя | ≥ 50 |
| Fill rate (≥ 1 отклик) | ≥ 70% |
| Time-to-first-bid (медиана) | < 60 мин |
| Assign rate | ≥ 40% |
| Completion rate | ≥ 60% |
| Отзывов оставлено | ≥ 100 |
| D7 retention (клиенты) | ≥ 25% |
| Мастеров, откликнувшихся 2+ недель | ≥ 30% |
| Parsing accuracy (ИИ) | ≥ 80% |

> **Решение после MVP:** При достижении ≥ 70% целей → масштабирование (V1). При < 50% → pivot / корректировка гипотез.

## Приложение A. Глоссарий

| Термин | Определение |
|--------|------------|
| **Reverse-marketplace** | Маркетплейс обратного спроса, где клиент создаёт спрос (заявку), а продавцы (мастера) предлагают решение |
| **Обратный аукцион** | Модель, при которой продавцы конкурируют за покупателя, предлагая лучшие условия |
| **ТЗ (Техническое задание)** | Структурированное описание работ, сгенерированное ИИ из свободного текста клиента |
| **Микротаск** | Подзадача комплексной заявки (например, «поклейка обоев» и «ремонт крана» — два микротаска) |
| **Отклик (Bid)** | Предложение мастера на ТЗ (цена, сроки, сообщение) |
| **Ликвидность маркетплейса** | Процент заявок, по которым состоялась сделка; ключевая метрика здоровья платформы |
| **Fill rate** | Доля опубликованных ТЗ, получивших ≥ 1 отклик |
| **Assign rate** | Доля ТЗ, по которым выбран исполнитель |
| **Completion rate** | Доля назначенных сделок, завершённых успешно |
| **North Star Metric** | Единая ключевая метрика продукта, отражающая ценность для пользователя |
| **AARRR** | Воронка метрик: Acquisition, Activation, Retention, Referral, Revenue |
| **CAC** | Customer Acquisition Cost — стоимость привлечения клиента |
| **LTV** | Lifetime Value — пожизненная ценность клиента |
| **MRR / ARR** | Monthly/Annual Recurring Revenue — регулярная выручка (SaaS) |
| **Churn rate** | Доля отписавшихся клиентов за период |
| **Graceful degradation** | Способность системы работать (в ограниченном режиме) при сбое компонента |
| **PII** | Personally Identifiable Information — персональные данные |
| **152-ФЗ** | Федеральный закон РФ «О персональных данных» |
